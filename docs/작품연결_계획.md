## 1. 개요 및 비즈니스 가치

### 1.1 왜 이 작업이 가장 중요하고 결정적인가?
- **기존의 한계:** 
  현재는 작품 수장고, 전시 캡션 출력기, 작가노트&SNS 도구가 제각각 분리되어 있어, 작가가 작품 하나를 등록할 때마다 제목, 연도, 크기, 재료, 가격을 각 화면에서 매번 손으로 새로 입력해야 했습니다.
- **개선 후 가치:** 
  작품을 수장고에 **단 한 번만 등록**하면,
  1. **전시 캡션 출력기**에서 "수장고에서 작품 불러오기" 클릭 한 번으로 벽면 캡션 카드가 즉시 완성되고,
  2. **작가노트&SNS**에서도 기존 작품을 불러와 미술평론풍 글과 인스타 캡션을 덧붙여 기존 작품에 온전히 누적 보관하며,
  3. **수장고 상세 도록**에서 해당 작품에 연결된 무손실 원본 사진, 캡션, 작가노트 3종을 한눈에 열람하고 관리하게 됩니다.
- **비즈니스 효과:**
  이 데이터 파이프라인이 바로 단순 메모장이나 엑셀, ChatGPT와 수장고를 격이 다르게 만드는 핵심 기능이며, 작가들이 **유료 멤버십(Pro/Studio)을 기꺼이 결제하게 만드는 결정적인 이유**가 됩니다.

### 2.2 클라우드 기능 현황 정밀 분석 및 실제 연동 가이드

#### A. 현재 실제로 작동하지 않는 기능 목록 (솔직한 진단)
1. **클라우드 원격 보관 (Supabase DB):**

2. **기기 간 실시간 동기화 (PC ↔ 스마트폰 ↔ 태블릿):**
   - 원격 DB 연동이 꺼져 있으므로, PC에서 등록한 작품이 스마트폰에 자동으로 나타나지 않습니다 (각 기기 브라우저에 독립 저장).
3. **타인(큐레이터/컬렉터)에게 보내는 프라이빗 도록 공유 링크:**

   - 따라서 이 링크를 카카오톡이나 이메일로 큐레이터(다른 사람 기기)에게 보내면, 큐레이터 컴퓨터에는 내 로컬 데이터가 없으므로 화면이 정상적으로 열리지 않습니다. (동일한 내 PC 브라우저 안에서만 열림)

### 2.3 자가 치유 엔진(Self-Healing)의 실체 및 안전 보강

#### A. 자가 치유 엔진의 원래 동작 분석
- `src/utils/archiveStorage.js`의 `saveArtworks` 함수에 내장된 방어 로직입니다.
- 브라우저 `localStorage`의 5MB 용량 한도 초과(`QuotaExceededError`) 시, **텍스트는 단 1글자도 지우지 않고 오직 이미지 base64에 대해서만**:
  - 1차: 중복 임시 필드(`previewImageUrl`) 제거
  - 2차: `imageUrl`이 150KB를 초과할 경우 이미 안전하게 생성된 `thumbnailUrl`로 교체
  - 3차: 극단적인 경우 뷰어용 이미지를 경량 썸네일로 전환하여 100% 저장 성공 보장

#### B. [매우 중요] 기존 문제점 확인 및 이번 계획에서의 안전 보강
1. **기존 문제점 확인:**
   - 기존 코드에서는 **IndexedDB 금고(`sujango_vault_db`)에 원본이 실제로 존재하는지 확인하지 않고**, `imageUrl.length > 150000` 조건만 보고 `thumbnailUrl`로 교체해 버렸습니다.
   - 또한 콘솔(`console.warn`)에만 남기고 **사용자 화면에는 아무런 알림 없이 조용히 교체**했습니다. 누나의 지적이 100% 맞습니다!
2. **이번 6단계에서의 안전 보강 조치:**
   - **① 금고 원본 사전 확인 (`hasOriginalInVault`):** 썸네일 교체 전, 해당 작품의 무손실 원본이 IndexedDB에 실제로 저장되어 있는지 비동기로 먼저 확인합니다.
   - **② 원본 미존재 시 강제 축소 원천 차단:** 만약 금고에 원본이 없는 작품이라면 **절대 썸네일로 축소하지 않습니다.** 대신 저장을 즉시 중단하고 사용자에게 팝업을 띄웁니다:
     `"브라우저 저장 공간이 부족합니다. 소중한 기록을 안전하게 보존하기 위해 백업 파일을 먼저 내려받거나 불필요한 작품을 정리해 주세요."`
   - **③ 투명한 알림 제공:** 원본이 금고에 안전하게 보존되어 있어 뷰어 사본만 경량화한 경우에도, 조용히 넘어가지 않고 화면에 안내 토스트를 띄웁니다:
     `"저장 공간 확보를 위해 화면 표시용 이미지를 경량화했습니다. 원본은 금고에 무손실 보존되어 있습니다."`
   - **④ 변환 중 엔진 잠금:** 6단계 마이그레이션이 진행되는 동안에는 `isMigrating = true` 플래그를 세워 **자가 치유 엔진이 일절 작동하지 못하도록 완전히 잠급니다.**

## 3. 새로운 공통 "작품 (Artwork)" 단일 데이터 구조

```typescript
interface Artwork {
  id: string;                     // 고유 ID (기존 호환: "art-1729512345678" 형태)
  title: string;                  // 국문 작품 제목 (필수, 예: "새벽의 경계")
  titleEn: string;                // 영문 작품 제목 (선택, 예: "The Boundary of Dawn")
  artist: string;                 // 작가 성명 (국문)
  artistEn: string;               // 작가 성명 (영문)
  year: string;                   // 제작 연도 (예: "2026")
  size: string;                   // 전체 규격 문자열 (예: "116.8 × 91.0 cm (50F)")
  sizeW?: string;                 // 가로 수치 (예: "116.8")
  sizeH?: string;                 // 세로 수치 (예: "91.0")
  sizeUnit?: 'cm' | 'inch';       // 단위
  canvasNo?: string;              // 캔버스 호수 (예: "50F", "10P", "가변크기")
  medium: string;                 // 국문 재료 (예: "한지에 수묵채색")
  mediumEn: string;               // 영문 재료 (예: "Ink and color on Korean paper")
  isNfs: boolean;                 // 비매품 여부 (true: 비매품, false: 판매가능)
  price: string;                  // 표시용 가격 (예: "3,500,000원" 또는 "NFS (비매품)")
  priceAmount?: number;           // 순수 숫자 가격 (예: 3500000)
  imageUrl: string;               // 뷰어/도록용 이미지
  thumbnailUrl?: string;          // 목록용 초경량 썸네일
  hasOriginalVault: boolean;      // IndexedDB 무손실 원본 금고 보관 여부
  statement?: string;             // 미술평론풍 정통 작가노트
  instaCaption?: string;          // 인스타그램 감성 캡션 & 해시태그
  blogStory?: string;             // 블로그 / 뉴스레터 작업실 비하인드
  keywords?: string;              // 핵심 키워드
  inspiration?: string;           // 영감 메모
  statementHistory?: {            // 직전 1개 버전 히스토리 (되돌리기용)
    statement: string;
    instaCaption: string;
    blogStory: string;
    savedAt: string;
  };
  schemaVersion: '6.0';           // 데이터 스키마 버전
  createdAt: string;              // 등록일
  updatedAt?: string;             // 최종 수정일
}
```

## 4. 데이터 안전 및 무손실 마이그레이션 아키텍처

### 4.1 백업 저장소 용량 사전 점검 및 IndexedDB 격리
1. **사전 용량 점검:** `navigator.storage.estimate()`를 호출하여 브라우저의 총 여유 공간을 점검합니다.
2. **IndexedDB 독립 백업 DB (`sujango_backup_db`) 격리 저장:**
   - 5MB 한도의 `localStorage`에 백업을 복사하다 생길 수 있는 용량 초과를 원천 차단하기 위해, 백업은 용량이 수백 MB 이상 보장되는 **독립 IndexedDB 데이터베이스 (`sujango_backup_db`)**에 저장합니다.
   - 실패 시 변환을 절대로 시작하지 않고, 사용자에게 **[백업 파일 내려받기 (JSON)]** 창을 먼저 띄웁니다.

### 4.2 안전한 3단계 변환 (Shadow Write & Dual Persistence in IndexedDB)
> **누나의 지적 반영:** `localStorage`에는 최종 변환된 데이터 **단 1벌**만 남깁니다!

1. **기존 키 원본 보존:** 
   - 기존 키(`artflow_artworks`)의 이름을 바꾸지 않고 그대로 둔 채, 내용을 **"복사"하여 IndexedDB(`sujango_backup_db`)의 `legacy_store`에 안전하게 보관**합니다.
2. **그림자 데이터 생성 (Shadow in IndexedDB):**
   - 새 형식으로 가공한 그림자 데이터 역시 `localStorage`가 아니라 **IndexedDB(`sujango_backup_db`)의 `shadow_store`에 기록**합니다.
3. **무결성 검증 통과 후에만 단 1벌 교체:**
   - IndexedDB의 그림자 데이터와 기존 원본의 개수, 텍스트 길이, ID가 100% 일치함을 검증합니다.
   - 검증이 완료된 시점에만 비로소 `localStorage`의 `artflow_artworks`를 새 형식 1벌로 안전하게 교체합니다.
   - 변환이 진행되는 동안에는 `isMigrating = true`로 자가 치유 엔진을 완전히 잠급니다.

### 4.3 IndexedDB 원본 사진 금고 (`sujango_vault_db`) 무결성 보존
- `sujango_vault_db`의 `artwork_originals` 스토어에 보관된 31.5MB 대용량 사진 바이너리(Blob)는 **이번 변환에서 내용을 1바이트도 수정하거나 재인코딩하지 않으며**, 오직 `artworkId` 키 연결 정합성만 확인합니다.

### 4.4 실패 처리 및 3회 재시도 제한 / 안심 배너
1. `schema_version = '6.0'`은 변환이 100% 성공했을 때만 기록합니다.
2. 실패 시 최대 3회까지만 재시도하며, 3회 실패 시 기존 데이터로 안전하게 계속 작동하도록 유지합니다.
3. 상단에 안심 배너 노출:
   `"데이터 정리 중 문제가 생겼어요. 작가님의 소중한 기록은 안전하게 남아 있으니 안심하세요."`
   배너 우측에 **[내 수장고 백업 파일 내려받기 (JSON)]** 버튼을 항상 제공합니다.

### 4.5 중복 작품 처리: 시스템 자동 병합 금지 및 수동 병합 UI
- **자동 병합 금지:** 제목과 연도가 같은 작품들을 시스템이 임의로 합치지 않습니다.
- **수동 병합 제안:** 수장고 상단에 `"같은 작품일 수 있어요"` 감지 배너를 띄우고, 작가가 직접 [비교 및 합치기] 팝업에서 사진과 작가노트를 확인한 뒤 합치거나 그대로 둘 수 있게 합니다.

### 4.6 기존 캡션 자동 연결 기준
- 작품 제목과 제작 연도가 **100% 일치할 때만** 자동으로 `artworkId`를 연결합니다.
- 일치하지 않는 캡션은 연결 없이(`artworkId: null`) 지금처럼 독립적으로 정상 사용 및 A4 출력이 가능합니다.

### 4.7 브라우저 데이터 영구 보존 요청 (`navigator.storage.persist()`)
- **아이폰 사파리 7일 미방문 삭제(Eviction) 방어:**
  - 앱 초기 구동 시 `navigator.storage && navigator.storage.persist()`를 자동 호출하여 브라우저에 데이터 영구 보존(Persistent Storage)을 요청합니다.
  - `navigator.storage.persisted()` 결과를 확인하여 `localStorage['sujango_storage_persisted']`에 기록합니다.
  - 만약 사파리 정책으로 인해 거절된 경우, 백업 안내 화면에 "홈 화면에 바로가기 추가(PWA)" 및 "정기 백업 파일 다운로드" 권장 문구를 부드럽게 노출합니다.

## 5. 도구별 세부 동작 방식 및 UX 원칙

### 5.1 전시 캡션 출력기 (`CaptionStudio`)
1. **수장고 작품 불러오기:** 상단에 `[수장고에서 작품 불러오기]` 버튼 제공. 선택 시 폼 자동 채움.
2. **캡션 단독 반영 원칙:** 캡션에서 수정한 내용은 **기본적으로 그 캡션에만 적용**됩니다. 작가가 명시적으로 `[✓] 수장고 작품 정보도 함께 수정하기`를 선택했을 때만 원본이 바뀝니다.
3. **수장고 변경 감지 알림:** 수장고에서 작품이 수정된 후 연결된 캡션을 열었을 때:
   `"수장고의 작품 정보가 변경되었습니다. 캡션에도 새 내용을 반영할까요?"` 확인 팝업 노출.

### 5.2 작가노트 스튜디오 (`StatementStudio`)
1. **기존 작품 불러오기 및 갱신:** 기존 작품을 불러와 글을 작성하고 저장하면, 중복 작품을 만들지 않고 해당 작품의 작가노트 필드만 갱신합니다.
2. **직전 1개 버전 히스토리 보관 및 되돌리기:**
   - 덮어쓰기 전 기존 글을 `statementHistory`에 보관합니다.
   - 상단에 **[이전 버전으로 되돌리기]** 버튼을 제공하여 클릭 시 직전 작성본으로 즉시 복원합니다.

### 5.3 버튼 명칭 및 아이콘 표준 (Zero-Tolerance)
- ❌ 이모지 전면 배제
- ✅ Lucide 아이콘 1개 + 정갈한 텍스트 조합:
  - `[전시 캡션 만들기]` (`FileText` 아이콘)
  - `[작가노트 다듬기]` (`Edit3` 아이콘)
  - `[수장고에서 작품 불러오기]` (`FolderOpen` 아이콘)
  - `[이전 버전으로 되돌리기]` (`RotateCcw` 아이콘)

## 6. Vercel Preview 테스트 및 기기별 검증 체크리스트

### 6.1 Vercel Preview 배포 전 테스트 절차
1. 로컬 단위 테스트 통과 후, 별도 프리뷰 브랜치(`feature/step6-artwork-pipeline`)를 생성하여 Vercel Preview URL을 생성합니다.
2. 작가님이 실제 스마트폰과 PC로 접속하여 테스트 샘플 데이터를 넣어보며 검증합니다.
3. 누나의 최종 승인이 떨어진 뒤에만 프로덕션 메인 배포를 진행합니다.

### 6.2 테스트용 샘플 데이터 세트
- **중복 작품 3쌍:**
  - 1쌍: 《새벽의 경계》(2026) 사진 있음 + 작가노트만 있는 중복본
  - 2쌍: 《푸른 잔상 No. 3》(2025) 사진 있음 + 캡션만 있는 중복본
  - 3쌍: 《무제》(2026) 동일 제목의 2점
- **캡션 10개 이상:**
  - 수장고 작품과 제목·연도가 100% 일치하는 캡션 5개
  - 연도가 다르거나 수장고에 없는 독립 캡션 5개
- **대용량 고해상도 사진 작품 1점:** (31.5MB 초대형 원본이 IndexedDB에 연결된 작품)
- **긴 작가노트가 있는 작품 2점:** (미술평론풍, 인스타, 블로그 3종 전문 포함)

### 6.3 기기별 세부 검증 체크리스트
- **아이폰 Safari:** 영구 보존(`persist`) 요청 결과 확인, 사파리 줌인 방지(16px), 375px 모바일 카드 터치 44px 이상 작동 확인.
- **안드로이드 Chrome:** 키보드 팝업 시 레이아웃 유지, IndexedDB 백업 및 무손실 원본 다운로드 정상 작동 확인.
- **PC Chrome / Whale:** 중복 작품 비교 병합 팝업 마우스 조작, 캡션 단독 수정 및 수장고 동기화 교차 확인, 31.5MB 원본 바이트 일치 확인.

> **문서 버전:** 1.1.0 (Step 6-1 피드백 전면 반영 개정판)  
> **작성일자:** 2026-10-21

## 1. 개요 및 비즈니스 가치

### 1.1 왜 이 작업이 가장 중요하고 결정적인가?
- **기존의 한계:** 
  현재는 작품 수장고, 전시 캡션 출력기, 작가노트&SNS 도구가 제각각 분리되어 있어, 작가가 작품 하나를 등록할 때마다 제목, 연도, 크기, 재료, 가격을 각 화면에서 매번 손으로 새로 입력해야 했습니다.
- **개선 후 가치:** 
  작품을 수장고에 **단 한 번만 등록**하면,
  1. **전시 캡션 출력기**에서 "수장고에서 작품 불러오기" 클릭 한 번으로 벽면 캡션 카드가 즉시 완성되고,
  2. **작가노트&SNS**에서도 기존 작품을 불러와 미술평론풍 글과 인스타 캡션을 덧붙여 기존 작품에 온전히 누적 보관하며,
  3. **수장고 상세 도록**에서 해당 작품에 연결된 무손실 원본 사진, 캡션, 작가노트 3종을 한눈에 열람하고 관리하게 됩니다.
- **비즈니스 효과:**
  이 데이터 파이프라인이 바로 단순 메모장이나 엑셀, ChatGPT와 수장고를 격이 다르게 만드는 핵심 기능이며, 작가들이 **유료 멤버십(Pro/Studio)을 기꺼이 결제하게 만드는 결정적인 이유**가 됩니다.

## 2. 현재 데이터 및 스토리지 현황 정밀 진단

### 2.1 무료 플랜 브라우저 로컬 저장소
| 영역 | 저장소 위치 | 현재 구조 및 특징 |
| :--- | :--- | :--- |
| **작품 수장고** | `localStorage['artflow_artworks_{userKey}']` | `id(art-Date.now())`, `title`, `artist`, `year`, `medium`, `size`, `price`, `isNfs`, `imageUrl`, `statement`, `instaCaption`, `blogStory`, `createdAt` |
| **무손실 원본 금고** | `IndexedDB ('sujango_vault_db' / 'artwork_originals')` | 31.5MB 초대형 파인아트 원본 파일이 Blob 형태로 무손실 영구 보관됨. 키는 `artworkId`. |
| **전시 캡션** | `localStorage['artflow_captions_{userKey}']` | `id(숫자)`, `artist`, `title`, `year`, `medium`, `size`, `price`, `isNfs`. 수장고 작품과의 연결 키(`artworkId`)가 없어 고립되어 있음. |
| **작가노트** | `StatementStudio` 폼 상태 | 저장 시 항상 새 작품 ID(`art-Date.now()`)로 수장고에 신규 생성되어 중복 데이터가 발생하는 원인이 됨. |

### 2.2 클라우드 데이터 (Supabase) 현재 상태 및 향후 연동 계획
- **현재 구현 상태:**
  - 코드 상으로 `syncUserProfile`, `saveSingleArtwork` 시 Supabase의 `artworks` 테이블로 비동기 동기화하는 로직이 작성되어 있습니다.
  - 그러나 현재 소스 코드(`src/utils/supabaseClient.js`)에는 데모용 키 필터링(`!url.includes('tkzacvmcqpytludkdpm')`)이 적용되어 있어, **실제 프로덕션 키가 주입되기 전까지는 클라우드 호출이 비활성화되고 오프라인 로컬 저장소로 100% 안전하게 동작**하고 있습니다.
- **향후 클라우드 연동 및 다중 기기/다중 탭 동시성 제어 계획:**
  1. **다중 탭 충돌 방지:** 브라우저의 `storage` 이벤트 리스너와 `BroadcastChannel('sujango_data_sync')`을 탑재합니다. 한 탭에서 데이터 변환이나 저장이 일어났을 때, 다른 탭에 즉시 알림을 전달하여 구형 화면이 옛 데이터로 덮어쓰지 못하도록 화면을 동기화합니다.
  2. **다중 기기 동시성 제어 (낙관적 락):** 각 작품 레코드에 `schema_version: '6.0'`과 `updatedAt: ISO string` 타임스탬프를 부여합니다. 서버나 다른 기기에서 데이터를 내려받을 때, 로컬 데이터보다 과거 시점의 구버전 데이터는 덮어쓰지 않고 무시합니다.

### 2.3 자가 치유 엔진(Self-Healing)의 정확한 실체 규명
- **어떤 동작을 하는가?**
  - `src/utils/archiveStorage.js`의 `saveArtworks` 함수에 내장된 방어 로직입니다.
  - 브라우저의 `localStorage`는 5MB 용량 한도가 있어, 사진이 포함된 작품이 많아지면 브라우저가 저장 자체를 거부(`QuotaExceededError`)합니다.
  - 이때 시스템은 **작가의 텍스트(작품명, 연도, 규격, 재료, 작가노트, 캡션 등)는 단 1글자도 지우지 않습니다.**
  - 오직 용량을 가장 많이 차지하는 **이미지 base64 문자열**에 대해서만:
    - 1차: 실시간 재생성 가능한 중복 임시 필드(`previewImageUrl`) 제거
    - 2차: `imageUrl`이 150KB를 초과할 경우 이미 안전하게 생성된 `thumbnailUrl`로 교체
    - 3차: 극단적인 경우 뷰어용 이미지를 경량 썸네일로 전환하여 100% 저장 성공 보장
- **원본 화질 손실 여부:**
  - 작가가 업로드한 초고화질 무손실 원본 사진(31.5MB 등)은 `localStorage`가 아닌 **용량 한도가 수백 MB에 달하는 IndexedDB(`sujango_vault_db`)에 안전하게 별도 보관**되어 있으므로 원본에는 1바이트의 손실도 없습니다.
- **이번 6단계 변환과의 충돌 여부:**
  - 이번 변환에서는 백업 데이터를 `localStorage`가 아닌 **별도의 IndexedDB 백업 스토어**에 기록하므로, `localStorage` 5MB 용량 압박을 유발하지 않으며 자가 치유 엔진과 완벽하게 조화롭게 동작합니다.

## 3. 새로운 공통 "작품 (Artwork)" 단일 데이터 구조

```typescript
interface Artwork {
  // [1. 고유 식별자]
  id: string;                     // 고유 ID (기존 호환: "art-1729512345678" 형태)

  // [2. 작품 기본 표기]
  title: string;                  // 국문 작품 제목 (필수, 예: "새벽의 경계")
  titleEn: string;                // 영문 작품 제목 (선택, 예: "The Boundary of Dawn")
  artist: string;                 // 작가 성명 (국문)
  artistEn: string;               // 작가 성명 (영문)
  year: string;                   // 제작 연도 (예: "2026")

  // [3. 규격 및 호수]
  size: string;                   // 표시용 전체 규격 문자열 (예: "116.8 × 91.0 cm (50F)")
  sizeW?: string;                 // 가로 수치 (예: "116.8")
  sizeH?: string;                 // 세로 수치 (예: "91.0")
  sizeUnit?: 'cm' | 'inch';       // 단위
  canvasNo?: string;              // 캔버스 호수 (예: "50F", "10P", "가변크기")

  // [4. 재료 및 기법]
  medium: string;                 // 국문 재료 (예: "한지에 수묵채색")
  mediumEn: string;               // 영문 재료 (예: "Ink and color on Korean paper")

  // [5. 가격 및 소장 상태]
  isNfs: boolean;                 // 비매품 여부 (true: 비매품/작가소장, false: 판매가능)
  price: string;                  // 표시용 가격 (예: "3,500,000원" 또는 "NFS (비매품)")
  priceAmount?: number;           // 순수 숫자 가격 (예: 3500000)

  // [6. 이미지 에셋]
  imageUrl: string;               // 브라우저 뷰어/도록용 경량 압축 이미지
  thumbnailUrl?: string;          // 목록용 초경량 썸네일
  hasOriginalVault: boolean;      // IndexedDB 무손실 원본 금고 보관 여부

  // [7. 연결된 작가노트 및 기록]
  statement?: string;             // 미술평론풍 정통 작가노트
  instaCaption?: string;          // 인스타그램 감성 캡션 & 해시태그
  blogStory?: string;             // 블로그 / 뉴스레터 작업실 비하인드
  keywords?: string;              // 작가 지정 핵심 키워드
  inspiration?: string;           // 창작 영감 / 동기 메모

  // [8. 작가노트 버전 히스토리 (최소 직전 1개 버전 영구 보존)]
  statementHistory?: {
    statement: string;
    instaCaption: string;
    blogStory: string;
    savedAt: string;              // 저장 일시
  };

  // [9. 시스템 메타데이터]
  schemaVersion: '6.0';           // 데이터 스키마 버전
  createdAt: string;              // 최초 등록일 (YYYY-MM-DD)
  updatedAt?: string;             // 최종 수정일 (YYYY-MM-DD)
}
```

## 4. 데이터 안전 및 무손실 마이그레이션 아키텍처

### 4.1 백업 저장소 용량 사전 점검 및 IndexedDB 백업 격리
1. **사전 용량 점검:** 
   - 변환 시작 전, 현재 브라우저에 저장된 데이터 총량(바이트)을 계산합니다.
   - `navigator.storage.estimate()` API를 호출하여 브라우저의 총 여유 공간을 사전 점검합니다.
2. **IndexedDB 전용 백업 DB (`sujango_backup_db`) 격리 저장:**
   - 용량 한도가 5MB에 불과한 `localStorage` 안에 백업을 복사하면 `QuotaExceededError`가 발생할 위험이 있습니다.
   - 따라서 백업은 용량이 수백 MB 이상 지원되는 **독립 IndexedDB 데이터베이스 (`sujango_backup_db`)**를 새로 열어, 기존의 모든 로컬스토리지 데이터를 원본 그대로 스냅샷 저장합니다.
3. **실패 시 강제 차단 및 파일 다운로드 안내:**
   - 만약 IndexedDB 백업 쓰기조차 실패하거나 지원되지 않는 환경이라면, **데이터 변환을 절대로 시작하지 않습니다.**
   - 화면에 즉시 안내 창을 띄우고: `"안전한 데이터 정리를 위해 백업 파일을 먼저 내려받아 주세요."` 알림과 함께 **JSON 백업 파일 자동 다운로드 창**을 열어줍니다.

### 4.2 안전한 3단계 변환 순서 (Shadow Write & Dual Persistence)
기존 데이터를 그 자리에서 덮어쓰지 않고, 단계별 검증을 거치는 **그림자 쓰기(Shadow Write)** 방식을 적용합니다.
1. **1단계 (Shadow Data 생성):** 기존 데이터를 읽어 새 형식으로 가공한 뒤, 임시 키(`artflow_artworks_v6_shadow`)에 기록합니다.
2. **2단계 (무결성 검증):**
   - 변환 전 작품 수와 변환 후 작품 수가 정확히 일치하는가?
   - 각 작품의 ID, 제목, 이미지, 작가노트 텍스트 길이가 100% 보존되었는가?
3. **3단계 (전환 및 Dual Persistence):**
   - 검증이 100% 통과했을 때만 정식 키(`artflow_artworks`)에 새 데이터를 활성화합니다.
   - **기존 키 원본 보존:** 기존 원본 키(`artflow_artworks_v5_legacy`, `artflow_captions_v5_legacy`)는 절대 삭제하지 않고 보관하여, 향후 최소 2번의 서비스 업데이트 동안 비상 복구용으로 영구 유지합니다.

### 4.3 IndexedDB 원본 사진 금고 (`sujango_vault_db`) 무결성 보존
- `sujango_vault_db`의 `artwork_originals` 스토어에 보관된 31.5MB 대용량 사진 바이너리(Blob)는 **이번 6단계 변환에서 내용을 1바이트도 수정하거나 재인코딩하지 않습니다.**
- 오직 각 작품 레코드의 `id`가 기존과 100% 동일하게 유지되는지만 검증하여, 무손실 원본 다운로드 파이프라인의 연결성을 완벽히 보장합니다.

### 4.4 실패 처리 및 3회 재시도 제한 / 긴급 복구 배너
1. **스키마 버전 기록 원칙:** `sujango_schema_version = '6.0'` 표시는 모든 변환과 무결성 검증이 100% 성공했을 때만 마지막에 단 한 번 기록합니다.
2. **재시도 3회 제한:** 변환 실패 시 무한 루프에 빠지지 않도록 시도 횟수 카운터(`sujango_migration_attempts`)를 두고, **최대 3회까지만 재시도**합니다.
3. **3회 실패 시 안전 모드 유지:**
   - 3회 실패 시 더 이상 변환을 시도하지 않고 기존 데이터 형식으로 서비스를 계속 정상 가동합니다.
   - 상단에 부드럽고 안심을 주는 배너 노출:
     `"데이터 정리 중 문제가 생겼어요. 작가님의 소중한 기록은 안전하게 남아 있으니 안심하세요."`
   - 배너 우측에 **[내 수장고 백업 파일 내려받기 (JSON)]** 버튼을 항상 제공합니다.

### 4.5 중복 작품 처리: 시스템 자동 병합 금지 및 수동 병합 UI
- **자동 병합 금지:** 작가노트를 저장하면서 제목과 연도가 같게 중복 생성된 작품들을 시스템이 임의로 하나로 합쳐버리면, 어느 한쪽의 소중한 사진이나 메모가 유실될 수 있습니다. 따라서 자동 병합은 절대 하지 않습니다.
- **"같은 작품일 수 있어요" 감지 배너:**
  - 제목과 연도가 동일한 작품들을 감지하면, 수장고 목록 상단에 은은한 알림 카드 노출:
    `"제목과 연도가 같은 작품 2점이 발견되었습니다. 하나의 작품으로 정리할까요?"`
  - 작가가 카드를 클릭하면 **비교 및 병합 팝업**이 뜹니다:
    - 왼쪽(작품 A의 사진, 캡션, 작가노트) vs 오른쪽(작품 B의 사진, 캡션, 작가노트)
    - [대표 사진 선택], [보존할 작가노트 선택]
    - 작가가 직접 확인하고 [하나로 합치기]를 눌렀을 때만 안전하게 통합하며, [그대로 두기]를 누르면 두 작품 모두 독립된 상태로 계속 유지됩니다.

### 4.6 기존 캡션 자동 연결 기준
- 기존에 작성해 둔 캡션 데이터(`artflow_captions`)와 수장고 작품을 연결할 때:
  - **작품 제목과 제작 연도가 100% 정확하게 일치할 때만** 자동으로 `artworkId`를 연결합니다.
  - 제목이나 연도가 조금이라도 다르거나 일치하는 작품이 없는 캡션은 **억지로 연결하지 않고 `artworkId: null` 상태로 둡니다.**
  - 연결되지 않은 캡션도 지금과 똑같이 아무런 제약 없이 수정하고, A4 규격으로 인쇄하고, 정상적으로 사용할 수 있습니다.

## 5. 도구별 세부 동작 방식 및 UX 원칙

### 5.1 전시 캡션 출력기 (`CaptionStudio`)
1. **수장고 작품 불러오기:**
   - 상단에 **[수장고에서 작품 불러오기]** 버튼 제공 (아이콘 1개 + 글자).
   - 누르면 수장고 작품 목록이 모바일 카드/그리드로 열리고, 작품을 선택하면 제목(국/영문), 연도, 재료(국/영문), 규격, 호수, 가격이 폼에 자동으로 채워집니다.
2. **캡션 수정 시 독립성 보장 (기본 캡션 단독 반영):**
   - 캡션에서 불러온 작품 정보를 수정할 때, **기본적으로는 그 캡션에만 적용**됩니다.
   - 작가가 명시적으로 `[✓] 수장고 작품 정보도 함께 수정하기` 체크박스를 선택했을 때만 수장고 원본 작품이 함께 갱신됩니다.
3. **수장고 작품 변경 시 캡션 감지 알림:**
   - 수장고에서 작품 정보를 수정한 뒤, 이전에 연결해 둔 캡션을 열었을 때:
     `"수장고의 작품 정보가 변경되었습니다. 캡션에도 새 내용을 반영할까요?"`
     확인 창을 띄워 작가가 원할 때만 [반영하기]를 누르도록 합니다.

### 5.2 작가노트 스튜디오 (`StatementStudio`)
1. **기존 작품 불러오기 및 업데이트:**
   - 상단에 **[수장고에서 작품 불러오기]** 버튼 제공.
   - 수장고에 이미 올려둔 작품을 선택하면 해당 작품의 사진과 규격, 기존 작성된 글이 로드됩니다.
   - 글을 수정하고 저장하면 새 작품을 중복 생성하지 않고, **해당 작품의 작가노트 필드만 갱신**합니다.
2. **작가노트 직전 1개 버전 히스토리 보관 및 되돌리기:**
   - 기존 작품에 새 작가노트를 덮어쓸 때, 직전 글 내용을 `statementHistory`에 항상 1개 버전 보관합니다.
   - 에디터 상단에 **[이전 버전으로 되돌리기]** 버튼을 제공하여, 실수로 글을 고쳤더라도 클릭 한 번으로 직전 작성본으로 즉시 복원할 수 있습니다.

### 5.3 수장고 상세 도록 (`ArchiveStudio`)
- 작품 상세 도록 모달 하단에 명확한 액션 버튼 2개 제공:
  - **[전시 캡션 만들기]**: 클릭 시 해당 작품 정보(제목, 연도, 재료, 규격)를 들고 캡션 스튜디오로 즉시 이동.
  - **[작가노트 다듬기]**: 클릭 시 해당 작품 정보를 들고 작가노트 스튜디오로 이동하여 바로 편집.

### 5.4 버튼 명칭 및 아이콘 표준 (Zero-Tolerance)
- ❌ 이모지(🏷️, ✍️, 🔍, 🏛️ 등) 사용 전면 배제
- ✅ **Lucide SVG 아이콘 1개 + 정갈하고 신뢰감 있는 글자** 조합 엄수:
  - `[전시 캡션 만들기]` (Lucide `FileText` 아이콘)
  - `[작가노트 다듬기]` (Lucide `Edit3` 아이콘)
  - `[수장고에서 작품 불러오기]` (Lucide `FolderOpen` 아이콘)
  - `[이전 버전으로 되돌리기]` (Lucide `RotateCcw` 아이콘)

## 6. Vercel Preview 테스트 및 기기별 검증 체크리스트

### 6.1 Vercel Preview 배포 전 테스트 절차
1. 로컬 환경에서 모든 단위 테스트를 통과한 후, 메인 프로덕션 브랜치가 아닌 **별도 프리뷰 브랜치(`feature/step6-artwork-pipeline`)**에 푸시하여 Vercel 프리뷰 배포 URL을 생성합니다.
2. 프리뷰 URL에서 작가님이 실제 스마트폰과 PC로 접속하여 아래 테스트 데이터 세트를 직접 넣어보며 검증합니다.
3. 완벽히 검증되고 누나의 승인이 떨어진 뒤에만 프로덕션 메인 배포를 진행합니다.

### 6.2 사전 테스트용 샘플 데이터 세트 구성 방안
개발자 도구 콘솔 또는 설정 화면의 [테스트 데이터 주입] 버튼을 통해 한 번에 넣을 수 있는 샘플 데이터 세트를 마련합니다:
- **중복 작품 3쌍:**
  - 1쌍: 《새벽의 경계》(2026) 사진 있음 + 작가노트만 있는 중복본
  - 2쌍: 《푸른 잔상 No. 3》(2025) 사진 있음 + 캡션만 있는 중복본
  - 3쌍: 《무제》(2026) 동일 제목의 2점
- **캡션 10개 이상:**
  - 수장고 작품과 제목·연도가 100% 일치하는 캡션 5개
  - 연도가 다르거나 수장고에 없는 독립 캡션 5개
- **대용량 고해상도 사진 작품 1점:** (31.5MB 초대형 원본이 IndexedDB에 연결된 작품)
- **긴 작가노트가 있는 작품 2점:** (미술평론풍, 인스타, 블로그 3종 전문 포함)

## 7. 순차 작업 로드맵 (6-2 세부 실행 단계)

한 번에 코드를 다 바꾸지 않고, **누나의 단계별 확인을 받으며 4개의 작은 단계로 진행**합니다.

```
[6-2-A: 데이터 엔진 & IndexedDB 안전 백업 구축]
       ↓ (누나 확인 및 Git 커밋)
[6-2-B: 전시 캡션 출력기 '수장고에서 작품 불러오기' 연동]
       ↓ (누나 확인 및 Git 커밋)
[6-2-C: 작가노트 스튜디오 '불러오기 & 버전 되돌리기' 연동]
       ↓ (누나 확인 및 Git 커밋)
[6-2-D: 상세 도록 양방향 브릿지 & Vercel Preview 기기별 교차 검증]
```

1. **Step 6-2-A (데이터 엔진 & 안전 백업 구축):**
   - 용량 점검 + `sujango_backup_db` IndexedDB 백업 엔진 구현.
   - 그림자 쓰기(Shadow Write) 및 기존 키 보존 마이그레이션 로직 구현.
2. **Step 6-2-B (전시 캡션 스튜디오 연동):**
   - `CaptionStudio.jsx`에 [수장고에서 작품 불러오기] 모달 구현.
   - 제목+연도 일치 캡션 자동 연결, 캡션 단독 수정 보장, 수장고 변경 감지 알림 구현.
3. **Step 6-2-C (작가노트 스튜디오 연동):**
   - `StatementStudio.jsx`에 [수장고에서 작품 불러오기] 모달 구현.
   - 기존 작품 업데이트 및 [이전 버전으로 되돌리기] 히스토리 기능 구현.
4. **Step 6-2-D (수장고 상세 도록 연결 & Vercel Preview 검증):**
   - `ArchiveStudio.jsx`에 [전시 캡션 만들기] / [작가노트 다듬기] 액션 버튼 연결.
   - 중복 작품 감지 및 수동 병합 UI 구현.
   - Vercel Preview 배포 및 3개 기기(아이폰/안드로이드/PC) 최종 검증.

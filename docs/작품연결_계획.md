# 수장고(Sujango) 6단계: 작품 연결 구조 설계 및 마이그레이션 계획서

> **문서 버전:** 1.0.0 (Step 6-1)  
> **작성일자:** 2026-10-21  
> **적용 대상:** 1인 미술 작가를 위한 프라이빗 수장고 (sujango.com)  
> **상태:** 누나(사용자) 승인 대기 중 (※ 본 단계에서는 코드를 일절 수정하지 않음)

---

## 1. 개요 및 추진 배경

### 1.1 왜 이 작업이 가장 중요하고 결정적인가?
- **기존의 한계:** 
  현재는 작품 수장고, 전시 캡션 출력기, 작가노트&SNS 도구가 서로 분리되어 있어, 작가가 작품을 하나 등록할 때마다 제목, 연도, 크기, 재료, 가격을 각 화면에서 매번 손으로 새로 입력해야 했습니다.
- **개선 후 가치:** 
  작품을 수장고에 **단 한 번만 등록**하면, 
  1. **전시 캡션 출력기**에서 "수장고에서 불러오기" 버튼 하나로 벽면 부착용 명패가 즉시 완성되고,
  2. **작가노트&SNS**에서도 기존 작품을 불러와 미술평론풍 글과 인스타 캡션을 손쉽게 덧붙일 수 있으며,
  3. **수장고 상세 도록**에서 해당 작품에 연결된 고해상도 사진, 캡션, 작가노트를 한눈에 열람하고 출력할 수 있게 됩니다.
- **비즈니스적 효과:**
  이 "원클릭 데이터 연결 파이프라인"이 바로 단순 범용 메모장이나 ChatGPT, 엑셀과 수장고를 완벽히 차별화하는 킬러 기능이며, 작가들이 **유료 멤버십(Pro/Studio)을 기꺼이 결제하게 되는 가장 강력한 이유**가 됩니다.

## 2. 현재 데이터 저장 위치 및 구조 분석

### 2.1 무료 플랜 (브라우저 로컬 저장소)
| 도구 / 영역 | 저장 위치 (로컬 키) | 현재 데이터 구조 및 한계점 |
| :--- | :--- | :--- |
| **나의 작품 수장고** | `localStorage['artflow_artworks_{userKey}']` | `id(art-Date.now())`, `title`, `artist`, `year`, `medium`, `size`, `price`, `isNfs`, `imageUrl`, `statement`, `instaCaption`, `blogStory`, `createdAt`<br>※ 작품의 기본 신상 정보와 AI 생성 글이 하나의 객체에 묶여 있으나, 영문 제목/재료 분리나 호수 필드가 구조화되어 있지 않음. |
| **무손실 원본 금고** | `IndexedDB ('sujango_raw_vault')` | 31.5MB 등 대용량 무손실 원본 사진 보관. `artworkId`를 키로 하여 완전 무손실 다운로드 지원. (성공 검증 완료) |
| **전시 캡션 출력기** | `localStorage['artflow_captions_{userKey}']` | `id(숫자)`, `artist`, `artistKo`, `title`, `titleKo`, `year`, `medium`, `size`, `price`, `isNfs`<br>※ 초기 로드 시 수장고 작품을 단순 복사하지만, 캡션에서 편집하거나 새로 등록한 내용이 **수장고 원본 작품과 링크(`artworkId`)되지 않고 완전히 별개로 고립**됨. |
| **작가노트 & SNS** | 폼 상태 중심 (임시) | 작가노트에서 새 글을 작성한 뒤 "수장고에 등록"을 누르면 항상 **새로운 작품(`art-Date.now()`)으로 신규 생성**됨. 기존 수장고에 이미 올려둔 작품을 불러와서 작가노트만 덧붙이는 기능이 없음. |

### 2.2 유료 플랜 (Supabase 클라우드 저장소)
- 테이블명: `artworks`
- 필드 구조: `id`, `user_email`, `title`, `year`, `medium`, `price`, `status`, `image_url`, `notes (JSON)`, `created_at`
- `notes` JSON 필드 안에 `client_id`, `size`, `statement`, `instaCaption`, `blogStory`를 패킹하여 브라우저 로컬 데이터와 양방향 동기화 중.

## 3. 새로운 공통 "작품 (Artwork)" 단일 데이터 구조 설계

수장고 작품 객체를 **'유일한 진실의 원천(Single Source of Truth)'**으로 확립합니다.

```typescript
interface Artwork {
  // [1. 고유 식별자]
  id: string;                     // 고유 ID (기존 호환: "art-1729512345678" 형태)

  // [2. 작품 기본 표기]
  title: string;                  // 국문 작품 제목 (필수, 예: "새벽의 경계")
  titleEn: string;                // 영문 작품 제목 (선택, 예: "The Boundary of Dawn")
  artist: string;                 // 작가 성명 (국문)
  artistEn: string;               // 작가 성명 (영문)
  year: string;                   // 제작 연도 (예: "2026")

  // [3. 규격 및 호수]
  size: string;                   // 표시용 전체 규격 문자열 (예: "116.8 × 91.0 cm (50F)")
  sizeW?: string;                 // 가로 수치 (예: "116.8")
  sizeH?: string;                 // 세로 수치 (예: "91.0")
  sizeUnit?: 'cm' | 'inch';       // 단위
  canvasNo?: string;              // 캔버스 호수 (예: "50F", "10P", "가변크기")

  // [4. 재료 및 기법]
  medium: string;                 // 국문 재료 (예: "한지에 수묵채색")
  mediumEn: string;               // 영문 재료 (예: "Ink and color on Korean paper")

  // [5. 가격 및 소장 상태]
  isNfs: boolean;                 // 비매품 여부 (true: 비매품/작가소장, false: 판매가능)
  price: string;                  // 표시용 가격 (예: "3,500,000원" 또는 "NFS (비매품)")
  priceAmount?: number;           // 순수 숫자 가격 (예: 3500000, 가계부/통계 정산용)

  // [6. 이미지 에셋]
  imageUrl: string;               // 브라우저 뷰어/도록용 경량 압축 이미지
  thumbnailUrl?: string;          // 목록용 초경량 썸네일
  hasOriginalVault: boolean;      // IndexedDB 무손실 대용량 원본 파일 보관 여부

  // [7. 연결된 작가노트 및 기록]
  statement?: string;             // 미술평론풍 정통 작가노트
  instaCaption?: string;          // 인스타그램 감성 캡션 & 해시태그
  blogStory?: string;             // 블로그 / 뉴스레터 작업실 비하인드
  keywords?: string;              // 작가 지정 핵심 키워드
  inspiration?: string;           // 창작 영감 / 동기 메모

  // [8. 시스템 메타데이터]
  createdAt: string;              // 최초 등록일 (YYYY-MM-DD)
  updatedAt?: string;             // 최종 수정일 (YYYY-MM-DD)
}
```

## 4. 캡션 및 작가노트와의 상호 연결 메커니즘

### 4.1 전시 캡션 출력기 (`CaptionStudio`) 연동 방식
```
[수장고 DB] ─────(작품 선택)────▶ [캡션 스튜디오 폼 자동 채움]
                                       │
                                   (내용 수정)
                                       ▼
                              [수장고 원본에도 동기화 반영 여부 확인]
```
1. **[수장고에서 작품 불러오기] 모달**:
   - 캡션 등록 폼 상단에 감성적인 돋보기/북마크 버튼 배치.
   - 클릭 시 수장고의 등록 작품들이 썸네일 + 제목 + 규격 카드로 팝업.
   - 작품을 탭하면 제목(국/영문), 연도, 재료(국/영문), 규격, 호수, 가격이 **1초 만에 폼에 자동 입력**됨.
2. **캡션 단독 입력 시 수장고 연동**:
   - 캡션 스튜디오에서 새로운 작품을 먼저 입력한 경우, 하단에 `[✓] 이 작품을 수장고에도 함께 등록하기` 체크박스 기본 활성화.
   - 캡션 카드가 저장될 때 수장고 작품 목록에도 자동으로 `saveSingleArtwork`가 실행되어 데이터 누락 방지.

### 4.2 작가노트 & SNS (`StatementStudio`) 연동 방식
1. **[기존 수장고 작품 불러오기]**:
   - 상단에 `[수장고에서 작품 불러오기]` 버튼 제공.
   - 이미 수장고에 등록해 둔 작품을 선택하면 이미지와 제목, 규격, 재료가 즉시 로드됨.
   - 이미 작성해 둔 작가노트가 있다면 에디터에 그대로 표시되어 이어서 수정 가능.
2. **저장 시 동작 분기**:
   - **기존 작품을 불러와서 수정한 경우**: 중복으로 새 작품을 만들지 않고, **기존 작품(`artworkId`)의 작가노트/인스타/블로그 필드만 깔끔하게 업데이트**.
   - **완전 새 작품을 입력한 경우**: 기존처럼 새로운 작품 ID(`art-Date.now()`)로 수장고에 신규 등록.

### 4.3 작품 상세 도록 (`ArchiveStudio`) 연동 방식
- 상세 도록 모달 하단에 원클릭 연결 액션 버튼 2개 신설:
  - `[🏷️ 이 작품 전시 캡션 출력하기]` → 누르면 캡션 스튜디오로 해당 작품 정보를 들고 바로 이동.
  - `[✍️ 작가노트 다시 다듬기]` → 누르면 작가노트 스튜디오로 이동하여 바로 내용 보강.

## 5. 기존 데이터 무손실 변환(Migration) 및 3중 안전망 설계

> **최우선 원칙:** 기존 사용자의 어떠한 데이터도 유실되지 않아야 함.

### 5.1 안전망 1단계: 변환 전 자동 백업 스냅샷
- 마이그레이션 함수가 실행되는 첫 줄에서 현재 `localStorage`의 모든 작품/캡션 데이터를 `sujango_backup_v5_pre_migration_{timestamp}` 키에 통째로 복사 저장.
- 또한 작가가 안심할 수 있도록 다운로드 폴더에 자동 백업 JSON 파일을 내려받을 수 있는 안전 복구 함수(`exportArchiveBackup`) 연계.

### 5.2 안전망 2단계: 멱등성(Idempotency) 보장
- `localStorage.getItem('sujango_schema_version') === '6.0'` 검사를 통해, 이미 새 구조로 변환된 환경에서는 마이그레이션이 **중복 실행되지 않도록 원천 차단**.

### 5.3 안전망 3단계: 트랜잭션 롤백(Rollback) 메커니즘
```javascript
try {
  // 1. 스냅샷 생성
  // 2. 데이터 마이그레이션 변환 수행
  // 3. 무결성 검증 (작품 수 일치 여부)
  // 4. sujango_schema_version = '6.0' 기록
} catch (error) {
  // 실패 감지 시 즉시 스냅샷 원본 데이터로 100% 롤백 복구
  console.error('[Migration] 변환 실패, 원본으로 자동 복구합니다:', error);
  rollbackToSnapshot();
}
```

## 7. 예상되는 위험 요소 및 사전 대비책

1. **위험: 브라우저 용량(5MB) 초과 에러**
   - **대비책:** 이미 구축된 `Self-Healing Storage Engine`을 유지합니다. 무손실 대용량 사진은 IndexedDB 금고에 두고, 로컬스토리지에는 경량 뷰어 사본만 보관하므로 100점 이상의 작품도 안전하게 보관됩니다.
2. **위험: 비로그인 및 데모 계정과의 충돌**
   - **대비책:** `getUserScopedKey`를 철저히 적용하여 작가 계정별로 데이터가 완벽히 격리되며, 시연용 데모 계정(김아라)과 실제 작가님의 데이터가 절대 섞이지 않습니다.
3. **위험: 모바일 화면에서의 작품 선택 팝업 깨짐**
   - **대비책:** M-1단계에서 확립한 모바일 반응형 규칙(터치 44px, 모바일 카드 뷰, 16px 폰트)을 100% 준수하여 작품 불러오기 모달을 슬림하고 직관적인 모바일 카드로 제작합니다.
